# ユーザーが確認する項目

人が決めるべきことを、各プロジェクトのstateに一度だけ登録する。`docs/user-checks.md` はそこから自動生成する。HOTL本体に各プロジェクトの具体的な質問を埋め込まない。

## 登録するもの

- 提示済み要件の承認はpresentから自動表示。approve/resetに追従する。未提示の要件を勝手に「承認してください」と一覧化しない。
- 本人の判断が必要な選択、既存の許可に含まれない実行、依頼された見た目の確認はaskで登録する。
- AIが調査・修正できる不具合や、通常の実装判断は確認待ちにしない。権限不足を仮定して一律に質問しない。

登録時には、何を判断するか・なぜ本人の判断が必要か・おすすめと選択肢・関連項目・保留する作業を具体化する。関連作業を止める必要がある項目だけblockingにする。ほかの許可済み作業は続ける。

## 更新するタイミング

判断の必要性はエージェントが判断してaskに登録し、その後の一覧更新・重複防止・回答状態はCLIが扱う。常駐して会話を自動解析する機能ではない。

新しい質問はチャットでも短く知らせ、一覧だけに黙って置かない。再開・進捗報告前はquestionsで読み直しsyncする。回答はreceiveの該当intentをanswerへ関連付ける。一つの回答で無関係な項目を閉じず、無回答・経過時間を承諾扱いしない。

対象ファイルを指定した質問は、対象変更を検出すると再提示が必要になる。以前の内容への回答を流用しない。不要になった質問は理由付きwithdrawで取り下げる。回答済み・取り下げ済みの履歴は残す。

permissionの回答は、その質問で特定した操作と対象に限る。CLIは自然言語の回答の意味や外部システムの権限を認証しない。実行前にはユーザーの実際の発言・対象版・ホストの権限を確認する。要件承認や実行権限を別の項目から拡大解釈しない。

blockingの確認待ちがある間はcompleteを拒否する。非blocking項目が残っていても作業完了を妨げないが、未回答事項を報告に残す。
