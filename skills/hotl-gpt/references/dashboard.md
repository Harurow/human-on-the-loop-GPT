# 開発ダッシュボード（全HOTLプロジェクト共通）

ゲーム、Web、業務アプリ、CLIなど全プロジェクトで `workbench/development-dashboard/index.html` を標準入口にする。
`init` と状態保存時に生成され、既存プロジェクトも `sync` で生成・修復できる。
Python標準ライブラリだけで動き、ブラウザーでローカルHTMLを開ける。常駐監視ではない。

```bash
python3 /absolute/skill/scripts/hotl.py --project /absolute/project sync
```

## 正本と更新

- 確認項目・承認・停止はstateから導出する。判断が必要なものだけaskへ登録し、不要な古い質問は理由付きwithdrawで現在の確認欄から外す。回答済み・撤回済みの履歴と元ファイルは残す。
- タスクの進捗はtasks.mdのチェックボックス、現在・次の順番・待ち/保留は同じファイルの「再開」が正本。現在のT-n、次のT-nを実行順で、待ちは理由と解除条件、更新日時を短く記す。進捗本文をHTMLや別JSONへ手で複写しない。
- タスクの区切り、判断待ち発生、進捗報告前、中断・引き継ぎ時に再開欄を更新しsyncする。statusのdashboard.stale/errorで再生成漏れ・不正な索引を確認する。HTMLにはstateとtasks、UI索引の更新時刻を表示する。ページを開いたまま自動更新する機能ではない。
- 固定入口docs/handoff.mdから `../workbench/development-dashboard/index.html` へ相対リンクを置く。既存入口を置換せず、再開手順の索引として加える。

## UIがある場合だけ画面索引を作る

`docs/ui-catalog.json` は画面名と既存の根拠・タスク・撮影物への参照だけを保持する。
UIがない場合は作らなくてよい。UIがあって未撮影ならmediaを空にし未取得と表示する。
各画面の現在の代表画像・動画だけを登録し、過去候補の大量表示で現在の確認を埋めない。
索引から外した資料は削除せず、必要なら既存文書から履歴として参照する。

```json
{
  "screens": [
    {
      "name": "ホーム画面",
      "decision": ["docs/design.md"],
      "integration": ["T-1"],
      "verification": ["docs/reviews/home.md"],
      "media": [
        {
          "path": "workbench/ui/home.png",
          "captured_at": "2026-09-12T10:00:00+09:00",
          "targets": {"src/home.py": "撮影時の対象ファイルのSHA-256"}
        }
      ]
    }
  ]
}
```

decisionの参照先で「未採用候補」「採用」を明記する。integrationには本編接続を扱うT-nを参照し、進捗はタスクから表示する。verificationの参照先で自動テスト・目視・実機・独立検証の対象版、条件、結果、未実施範囲を区別する。画像の掲載やタスクの完了だけで採用・接続・検証合格と扱わない。

pathと文書参照はプロジェクト内の相対ファイルパス。外部URL、絶対パス、親への脱出、シンボリックリンクは禁止。欠落ファイルは未取得/リンク切れとして表示する。PNG/JPEG/WebP/GIFとMP4/WebM/MOVを埋め込める（再生可否はブラウザーの形式対応による）。targetsには撮影に影響したコード・素材を十分な範囲で登録する。未登録・変更・欠落は「現在版との一致未確認 / 古い資料」と表示し、一致も登録範囲だけの確認であって実機検証の代用にはしない。生成前にエージェントが現在画面と撮影条件を照合する。

## Git管理

最初にgit status、リポジトリのルート、remote、既存ignoreを確認する。未管理という推測を事実にしない。既存の変更・履歴を保持し、配布元リポジトリを対象アプリとして初期化しない。

生成コード、仕様、tasks、UI索引、必要最小限の検証記録はGit管理する。再生成できる `workbench/development-dashboard/index.html` は原則ignoreし、レビュー対象snapshotからも除外する。既に追跡済みならユーザー変更を確認して移行する。元の仕様・コードをignoreしない。

ダッシュボードHTML・確認用キャプチャ・動画は `workbench/` に置きGit対象外にする。Git LFSにも入れない。生成コード・テンプレート・軽量設定・仕様・状態正本・テキスト検証記録をGit管理する。Git除外は削除許可ではない。採用素材や再撮影できない重要記録を一括削除せず、必要ならプロジェクトの既存保管方針へ分離する。Git外の撮影物は別端末で欠け得るので、検証記録へ対象版、撮影手順、保管先、未取得時の扱いを記す。既存artifactsから移行するときはファイルを保持して生成元・参照・入口を更新し、麻雀など別担当の案件を共通側から同時編集しない。

CLIはgitignoreに `/workbench/` を差分追加し、handoffがなければ正本への固定索引を作る。既存handoffは上書きしないので、初回適用時にエージェントが開発ダッシュボードへのリンクを差分追加する。既にGit追跡済みの生成物はignoreだけで解除されないため、実ファイルを保持して個別に追跡除外する。配布元更新でリンク式インストールには反映されるが、コピー式はinstall --forceのバックアップ付き更新が必要。既存プロジェクトの生成HTMLは各対象でsyncするまで更新されない。


## プロジェクトごとの上書き

標準は左上のアプリ名の直下に今の確認事項を表示し、続いて現在/次順/待ち、タスク、UIを置く。要点を直接表示し、詳細の正本へリンクする。`docs/dashboard.json` で表示名・順序・画面索引を上書きできる（省略時は標準）。状態や承認本文は入れない。

```json
{"title":"アプリ名", "sections":["checks","progress","ui","tasks"], "ui_catalog":"docs/ui-catalog.json"}
```

sectionsはchecks/progress/tasks/uiをそれぞれ一度含める。プロジェクト固有の独自生成器でさらに配置を変える場合はAGENTS.mdに定義の正本・生成コマンド・出力入口を記し、同じstate/tasksとUI索引を参照する。独自HTMLを標準生成先に置かず、固定handoffから選んだ入口へリンクする。標準CLIが任意コードを自動実行する機能はない。
