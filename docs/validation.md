## 独立した手順確認

別コンテキストのエージェントへ、スキルと「ローカル文字数カウンターを作る」シナリオを渡し、
隔離した一時プロジェクトで CLI を操作してもらった。
初回はフェーズ進行、承認と不具合の分離、タスク関連付け、再送、停止/再開、snapshot、
未完了タスクでの完了拒否、同一実装者のレビュー拒否まで確認した。

検出した次の2点を修正した。

1. 先に届いた未処理の再開指示が、後から来た停止を解除できた。
   最新 stop より後の resume だけを許可し、回帰テストを追加。
2. 「承認と修正の混在は再提示」という文面が、既存基準内の不具合にも適用されるように読めた。
   要件変更に限定し、不具合報告は承認とは別の入力として開発で処理する旨を明記。

同じ独立担当による修正後の再確認も成功。古い resume は状態と revision を変えずに
終了コード2で拒否され、新しい resume は承認を維持して再開できた。
承認と不具合が同時に届く場合も、承認後に不具合だけが未処理で残り、
未完了タスクへの関連付けで再承認なく処理できた。完了済みタスクへの関連付けは拒否された。

この確認はフレームワークの操作テスト。サンプル製品に対する独立した受け入れ検証の完了を
意味しない。コード上の回帰テストで reviewer ID を指定することも、実在する検証者の認証ではない。
